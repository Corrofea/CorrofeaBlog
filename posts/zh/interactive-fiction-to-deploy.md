# 从写一个交互小说到部署：一篇关于「百年孤独」的技术笔记

> 写于 2025.08.05 | 前端 · Node.js · 部署

## 缘起

最近重读了马尔克斯的《百年孤独》。这一次读，我突然想到：如果把布恩迪亚家族的故事做成一个交互式叙事体验会怎样？读者可以穿梭于马孔多的不同年代，触摸那些注定重复的命运。

这个想法一旦产生，就再也停不下来。

## 选型

交互小说的工具有很多。Ink、Twine、Ren'Py……最终我选择了 Twine，原因很简单：它生成的是纯 HTML 文件，不需要任何运行时，可以直接部署。

对于个人博客来说，没有什么比"一个文件丢上去就能跑"更让人安心的了。

## 技术实现

Twine 使用 Harlowe 故事格式。本质上，每个 passage 就是一个 HTML 片段，passage 之间的跳转通过 `[[链接文本->目标Passage]]` 语法完成。

```javascript
// 在 Twine 中嵌入自定义逻辑
<<set $hasReadManuscript = false>>
<<if $hasReadManuscript>>
  你认出了梅尔基亚德斯的笔迹。
<<else>>
  这些符号对你来说毫无意义。
<<endif>>
```

真正有趣的部分是部署。我不想把整个 Twine 编辑器暴露给读者，于是写了一个简单的后处理脚本，把生成的 HTML 中的 Twine 特有标记清理掉，只保留纯净的交互逻辑。

## Nginx 上的一个小坑

把 HTML 文件丢到 Nginx 上之后，点击 passage 跳转时，URL 会带上 `#` 锚点。Nginx 默认不会记录 `#` 后面的内容到 access log 里，因为那是客户端行为。如果你想统计读者的阅读路径，需要在 JS 里手动发送事件。

## 写完的感觉

交互小说和写博客有一个本质的相似之处：它们都在构建一个叙事空间。区别只是，博客的路径是线性的，而交互小说的路径是网状的。

当读者在马孔多的雨林中迷路时，他们可能比读一篇直线叙述更接近布恩迪亚上校的真实感受。
